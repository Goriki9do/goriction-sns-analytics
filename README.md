# ゴリクション自作SNS分析

有料の中継サービス（Windsor.aiなど）を使わず、各SNSの公式APIから直接データを取得し、
ローカルのSQLite／CSVに保存するツール群。ChatGPT／Claudeに必要なCSVを渡して分析する。

## 方針

- 投稿・削除・公開設定変更などの書き込み系操作は実装しない（取得のみ）。
- 課金、既存設定の大幅変更、外部公開、認証情報の外部送信は実施直前に本人確認する。
- コメントは「件数」ではなく、返信を含めた本人除外後の「ユニーク投稿者数」を主指標とする。
  取得できない場合は「正確な人数」と表示せず、不明／部分取得として扱う。

## 対応状況

| SNS | 状態 | 備考 |
|---|---|---|
| YouTube | 実装済み（別環境で運用中） | Data API／Analytics APIで取得。詳細は運用者のNotion参照 |
| TikTok | 検討中 | Display APIは自分の投稿の一覧・基本統計のみ取得可。コメントの人数集計は公式Research API（研究者限定）でしか提供されておらず利用不可。TikTok Studioからのブラウザ経由CSVエクスポート（手動ログイン＋自動ダウンロード）で補う方向を検討中 |
| Instagram | 未着手 | Graph API利用はBusiness／Creatorアカウントが前提（個人アカウントは不可） |
| X | 未着手 | 無料枠では分析用途がほぼ使えない見込み |

## このリポジトリについて

YouTube版は現在、運用者のローカル環境（Windows PC）で構築・運用されており、このリポジトリには
まだコードを移していない。ここでは主にTikTok以降の新規SNS対応を実装していく。

## 今後の実装方針（SNS追加時の共通ルール）

1. 各SNSの公式資料で、本人アカウントの分析・コメント・全返信・安定した投稿者IDを取得できるか確認する。
   アカウント種別、審査、スコープ、料金、取得上限も調べる。
2. 最小の1投稿で認証→取得→保存を先に通す。課金や外部公開が必要なら、実施前に本人確認する。
3. SNSごとに認証・取得処理を分離し、投稿IDとSNS・アカウントIDの組み合わせで保存する。
4. 単位・日付タイムゾーン・更新遅延・指標の定義をSNSごとに記録する（同じ「再生数」でも意味が異なる場合がある）。
5. コメント人数は、取得可能な場合のみ全ページ・全返信→安定IDで重複排除→本人ID除外という手順を踏む。
   取得できない場合は「不明」「部分取得」と明示し、SNS間で同一人物と推定しない。
6. 再実行時の重複防止、重複期間の再取得、欠測と0の区別、API失敗時の既存データ保持を検証する。
